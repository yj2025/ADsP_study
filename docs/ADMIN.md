# 관리자 콘텐츠 관리

## 접근과 권한

서버 실행 후 `http://127.0.0.1:4173/#admin`에 접속합니다. 관리자 계정으로 로그인하면 메뉴에 **콘텐츠 관리**가 표시됩니다. 일반 회원이나 게스트는 가져오기 API를 호출해도 각각 403 또는 401 응답으로 차단됩니다.

새로 가입한 계정과 기존 계정은 기본적으로 `member`입니다. 최초 가입자를 자동으로 관리자로 만들지 않으며, 가입 요청에 `role=admin`을 넣어도 권한을 얻을 수 없습니다. 서버 운영자가 기존 가입 계정을 다음 명령으로 지정합니다.

```powershell
node scripts/manage-admin.cjs grant 가입이메일@example.com
node scripts/manage-admin.cjs revoke 가입이메일@example.com

# 별도 환경의 DB를 지정할 경우
node scripts/manage-admin.cjs grant 가입이메일@example.com --database data/practice.sqlite
```

권한은 `users.role`에 저장합니다. 지정 후 페이지를 새로고침하면 기존 로그인 세션에서도 메뉴가 반영됩니다. 권한 해제는 API에서 즉시 적용되며 대기 중인 검증 결과도 취소됩니다. 비밀번호나 계정을 새로 만들지 않습니다.

## 업로드 → 파일 검증 → 초안 저장 → 검수 및 공개

1. UTF-8 CSV 또는 JSON 파일을 선택합니다. 최대 2MB, 개념·문제 합계 최대 1,000개를 지원합니다.
2. 등록된 과목과 단원을 선택합니다.
3. **파일 검증하기**를 누릅니다. 이 단계에서는 콘텐츠를 저장하지 않습니다.
4. 대상 과목·단원, 개념·문제 수, 항목 ID와 제목, 경고를 확인합니다. 목록은 처음 100개까지 표시합니다.
5. 검증이 성공하면 **검증한 콘텐츠를 초안으로 저장**을 누릅니다. 초안은 학습 화면에 표시되지 않습니다.
6. **저장한 초안 검수하기**를 누르거나 **콘텐츠 검수와 공개**에서 단원과 초안 상태를 선택해 목록을 불러옵니다.
7. 항목을 펼쳐 개념 본문, 문제 보기·정답·해설, 출처를 확인합니다. 공개할 항목을 선택하고 **검수 완료 및 공개**를 누릅니다. 문제와 연결된 개념이 아직 초안이면 함께 선택하거나 개념을 먼저 공개합니다.
8. 공개한 콘텐츠는 학습 화면에 반영됩니다. **공개 완료** 상태로 목록을 불러오면 공개된 항목과 일시를 확인할 수 있습니다.

이미 학습 화면에 있던 항목은 공개 상태를 유지합니다. 신규 공개에는 검수 관리자와 시각을 기록하며, 선택 항목 전체가 한 번에 공개되거나 모두 취소됩니다.

파일이나 범위를 바꾸면 화면의 검증 결과가 취소됩니다. 오류가 있으면 첫 오류를 표시하므로 수정한 파일을 다시 선택해 검증해 주세요. 서버는 관리자별로 가장 최근에 성공한 검증만 보관하고, 검증 결과를 10분 후 만료시킵니다. 다른 로그인 세션이나 다른 관리자는 그 결과로 저장할 수 없습니다. 저장 성공한 검증 결과는 재사용할 수 없습니다.

## 파일 형식과 단원 배정

기본 예제는 `content/example.json`, `content/example.csv`입니다. 자세한 열과 필드는 [콘텐츠 가져오기 가이드](../content/README.md)를 참고하세요.

- 웹 화면은 기존 과목·단원에 `lessons`, `questions`만 추가합니다. 과목·단원 정의(`subjects`, `units`)가 들어 있는 파일은 CLI로 가져옵니다.
- 모든 신규 개념은 화면에서 선택한 단원에 배정합니다. 파일에 다른 `unit_id`가 있으면 선택한 단원을 사용하며 검증 결과에 경고를 표시합니다.
- 문제는 같은 파일의 신규 개념 또는 선택 단원에 이미 있는 개념을 참조할 수 있습니다. 다른 단원의 기존 개념을 참조하는 문제는 거부됩니다.
- JSON의 정답 인덱스는 0~3, CSV의 보기 번호는 1~4입니다.
- ID 중복, 필수 필드 누락, 잘못된 참조·정답·보기, 파일 형식 오류를 검사합니다. 기존 항목 덮어쓰기는 지원하지 않습니다.

## 저장과 기록 보존

검증 결과는 서버의 `content_uploads`에 사용자·세션에 귀속된 임시 항목으로 저장됩니다. 최종 저장 시 클라이언트가 보낸 본문을 다시 믿지 않고, 검증한 항목을 서버에서 읽어 재검사합니다. 검증 이후 다른 가져오기로 ID가 중복되었으면 전체 저장을 취소하고 재검증을 안내합니다.

콘텐츠 추가, 검증 결과 사용 처리, `content_imports`의 작업 이력 기록은 한 트랜잭션으로 처리합니다. 작업 이력에는 관리자 ID, 파일 이름, 대상 단원, 추가 건수, 저장 시각이 기록됩니다. 학습·오답·계정 데이터는 수정하지 않습니다. 콘텐츠 파일의 문자열은 HTML로 실행하지 않습니다.

학습 기록의 기존 저장 기능은 그대로 유지되며, 가져오기 후 콘텐츠 수가 늘어나면 단원 진도율은 달라질 수 있습니다. 실제 콘텐츠·학습·계정 DB는 기존처럼 `data/study.sqlite`이며 이 폴더는 Git에 포함되지 않습니다.

## 테스트

`npm test`에는 관리자 HTTP 통합 테스트가 포함됩니다. 테스트는 임시 DB에서만 회원가입·권한 지정·파일 검증·저장을 수행합니다. 권한 차단, 교차 출처 차단, 다른 세션의 검증 결과 차단, 만료, 권한 해제, 중복 저장, 검증 후 ID 충돌, 트랜잭션 취소와 학습 기록 보존을 확인합니다.

## 공개 문제 정정

검수 상태를 **공개 완료**로 바꾸고 문제의 **공개 내리기**를 선택합니다. **초안** 목록에서 문제 본문, 보기, 정답, 해설을 수정하고 검수 후 다시 공개할 수 있습니다. 문제 ID와 연결 개념은 유지됩니다. 기존 답안과 오답 메모는 보존되며 정답이 바뀌면 공개 후 새 정답을 기준으로 표시됩니다. 내려간 문제를 포함한 진행 중인 문제 세트나 모의고사는 재접속 후 다시 구성해야 할 수 있습니다.

## 개념 수정과 초안 버전

공개 완료 목록에서 **개념 수정**을 열어 제목과 본문을 작성합니다. 수정안은 초안 목록에서 확인할 수 있으며, 검수 후 공개하면 같은 개념 ID의 제목과 본문이 갱신됩니다. 검수 전까지 학습 화면에는 기존 개념이 표시됩니다. 기존 서식이 있는 개념을 수정할 때는 전체 본문을 일반 텍스트로 작성합니다.

개념과 문제의 수정·공개 요청에는 화면에 표시된 버전이 사용됩니다. 다른 관리자가 먼저 내용을 바꿨다면 저장이나 공개가 거부됩니다. 목록을 다시 불러온 뒤 최신 내용을 확인하고 진행합니다.
